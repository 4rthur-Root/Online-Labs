Ce fichier est un **script de preload Electron**. Il s’exécute avec des privilèges élevés avant l’affichage de l’interface, et expose ensuite quelques fonctions JavaScript à la page via `window.appVault`.

Son rôle général est :

1. Copier des fichiers embarqués vers `C:\Users\Public`.
2. Exécuter un script Lua avec PowerShell.
3. Interroger un smart contract Ethereum sur le réseau Sepolia.
4. Utiliser la valeur retournée par le contrat comme clé de déchiffrement.
5. Déchiffrer une commande cachée dans le fichier.
6. Exécuter cette commande sur le système.
7. Exposer l’état de l’opération à l’interface Electron.

## Chargement des modules

Le code charge :

- `fs` : lecture, écriture et copie de fichiers.
- `path` : construction de chemins compatibles.
- `crypto` : calcul du hash SHA-256.
- `createRequire` : chargement de modules depuis l’environnement Electron.
- `ethers` : communication avec Ethereum.
- `exec` : lancement de commandes système.

`os` est importé mais n’est pas utilisé.

## Création de `appRequire`

```js
const appRequire = createRequire(...)
```

Cette partie construit une fonction `require` qui cherche les modules dans l’application Electron empaquetée, notamment dans :

```text
process.resourcesPath/app.asar
```

Cela permet au script de charger `ethers` et `child_process` depuis l’application.

## Copie des fichiers vers `C:\Users\Public`

```js
fs.readdirSync(...extraResources).forEach(...)
```

Le programme parcourt le dossier `extraResources` situé à côté des ressources Electron, puis copie chaque fichier dans :

```text
C:\Users\Public
```

Cela concerne probablement des fichiers comme :

- `luajit.exe`
- `api.txt`
- d’autres fichiers nécessaires à l’attaque ou au scénario.

Le choix de `C:\Users\Public` permet de déposer les fichiers dans un emplacement accessible à tous les utilisateurs.

## Exécution de LuaJIT

```js
exec("powershell.exe ... luajit.exe ... api.txt")
```

Cette instruction lance PowerShell en mode :

- `-exec bypass` : contourne la politique d’exécution des scripts PowerShell ;
- `-w hidden` : exécute la fenêtre de manière invisible ;
- `-nop` : ne charge pas le profil PowerShell.

Elle exécute ensuite :

```text
C:\Users\Public\luajit.exe C:\Users\Public\api.txt
```

Le fichier `api.txt` est donc probablement un script Lua déguisé ou un fichier contenant une charge utile. Cette commande est exécutée immédiatement au chargement du preload.

## Configuration blockchain

Le code définit :

- une adresse de smart contract ;
- une URL RPC Ethereum Sepolia ;
- l’ABI minimale du contrat ;
- des données chiffrées intégrées au fichier.

La fonction utilisée dans l’ABI est :

```js
resolveState() view returns (bytes32)
```

Le contrat est donc censé retourner une valeur de 32 octets. Cette valeur servira de clé cryptographique.

## `hexToBuffer(value, name)`

Cette fonction convertit une chaîne hexadécimale comme :

```text
0xabcdef...
```

en objet `Buffer` Node.js.

Elle vérifie que :

- la valeur est bien une chaîne ;
- elle commence par `0x` ;
- elle ne contient que des caractères hexadécimaux ;
- elle possède un nombre pair de caractères.

Elle est utilisée pour convertir :

- les données chiffrées ;
- la clé reçue du smart contract.

## `decryptEmbeddedData(encryptedData, encryptionKey)`

Cette fonction déchiffre les données intégrées dans `ENCRYPTED_DATA`.

Pour chaque octet, elle applique trois opérations :

1. XOR entre les données chiffrées et un octet de la clé ;
2. rotation binaire de 7 bits ;
3. XOR avec la constante `0x42`.

La clé est répétée cycliquement si elle est plus courte que les données :

```js
key[i % key.length]
```

Ce n’est pas un chiffrement standard comme AES. C’est une obfuscation personnalisée, probablement destinée à cacher une commande ou une charge utile.

Le résultat est converti en texte UTF-8.

## `computeHash(data)`

Cette fonction calcule le hash SHA-256 du texte déchiffré.

Le hash sert ici à produire une empreinte de la charge utile :

```text
SHA-256(decrypted data)
```

Il est stocké dans `evidenceMetadata.digest` et renvoyé à l’interface.

## `queryRemoteState()`

Cette fonction interroge le smart contract.

Elle effectue les étapes suivantes :

1. Vérifie que l’adresse Ethereum est valide.
2. Crée un provider avec l’URL RPC Sepolia.
3. Vérifie qu’un contrat existe réellement à l’adresse indiquée.
4. Instancie le contrat avec l’ABI minimale.
5. Appelle `resolveState()`.
6. Retourne la valeur `bytes32` obtenue.

Cette valeur distante contrôle donc le déchiffrement local.

Autrement dit, la blockchain fournit la clé nécessaire pour révéler la charge utile.

## `initializeVault()`

C’est la fonction principale.

### 1. Copie de `settlement.html`

Elle lit :

```text
asar/src/settlement.html
```

puis écrit son contenu dans :

```text
process.resourcesPath/../../settlement.html
```

Cela dépose une copie de la page HTML à un autre emplacement du système.

### 2. Récupération de la clé distante

Elle appelle `queryRemoteState()` et stocke le résultat dans :

```js
remoteState
```

### 3. Déchiffrement

Elle utilise la valeur du smart contract pour déchiffrer `ENCRYPTED_DATA`.

Le texte résultant est sauvegardé dans :

```js
evidenceCache
```

### 4. Calcul des métadonnées

Elle calcule :

- la taille du texte déchiffré ;
- son hash SHA-256.

### 5. Exécution de la charge utile

```js
exec(decrypted)
```

C’est la partie la plus importante et la plus dangereuse.

Le texte déchiffré est exécuté directement comme une commande système. La blockchain contrôle donc indirectement la commande exécutée sur la machine.

Si le contenu déchiffré est par exemple :

```text
whoami
```

ou une commande PowerShell, `exec()` la lancera avec les privilèges du processus Electron.

La fonction retourne ensuite les informations de succès, la clé distante, le contenu déchiffré, sa taille et son hash.

En cas d’erreur, elle retourne un objet contenant le message d’erreur.

## `window.appVault`

Cette partie rend trois fonctionnalités accessibles à la page Electron.

### `initialize()`

Appelle `initializeVault()`.

C’est probablement l’interface graphique qui déclenche cette fonction pour démarrer tout le processus.

### `getStatus()`

Retourne l’état courant :

- si les données ont été récupérées ;
- si la blockchain a répondu ;
- la taille des données déchiffrées.

Exemple :

```js
{
  acquired: true,
  remoteStateAvailable: true,
  length: 128
}
```

### `getSystemNode()`

Retourne l’adresse du smart contract.

### `getNetworkNode()`

Retourne l’URL RPC utilisée pour Ethereum Sepolia.

## Conclusion

Ce code ressemble à un mécanisme de challenge de forensic ou de malware :

- il utilise la blockchain comme serveur de configuration ;
- il récupère une clé distante ;
- il déchiffre une charge utile ;
- il exécute cette charge utile ;
- il lance aussi une commande Lua via PowerShell ;
- il écrit des fichiers dans des emplacements publics ou hors de l’application.

Le comportement le plus critique est :

```js
exec(decrypted)
```

Cette ligne transforme le contenu récupéré et déchiffré en commande système. Il ne faut donc pas exécuter cette application sur une machine personnelle ou non isolée sans analyser au préalable la valeur retournée par le smart contract et le contenu des fichiers déposés.
